CurseForge 預算指南

本文件定義 EventAlertMod Retail rewrite 的發佈資源規則。

2026-08-21 新根封裝與部署治理（現行）

插件 ZIP

  • 唯一來源是 D:\Project_EventAlertMod\EventAlertMod，不得從根目錄散落的 Core/、UI/ 或 Dist staging 拼包。
  • ZIP 內必須是 EventAlertMod/ exact tree，保留插件資料夾內的 EventAlertMod.toc、Core/、Data/、Debug/、Locale/、Managers/、Media/、Services/、UI/ 及插件內公開說明；不納入 .AI、Deploy、Dist、測試、備份或本機 deploy。
  • 產物寫入 D:\Project_EventAlertMod\Dist；Dist 為 ignored 本機產物區，不提交 Git，也不直接部署成 AddOn 來源。

原始碼 ZIP（2026-09-04 停用聲明）

  • 停用規範：自 2026-09-04 起，GitHub Release 於發布 Tag 時會自動為版本打包完整 Source code（zip 與 tar.gz）。本機發布流程全面停用專案 SRC 打包，亦不再上傳 SRC 附件至 GitHub Release，杜絕資源浪費與重複封裝。
  • 歷史規則保留：原腳本 Deploy/Build-SourcePackage.ps1 僅作為歷史證據與 AST 契約靜態檢驗之用，不再納入本機日常或自動化發布流程。

部署選擇與安全前檢

  • Deploy/Deploy-EventAlertMod.ps1 先查 Windows Registry，再以 Deploy/DeploymentTargets.json 的 wowRoot 作 JSON fallback；互動模式可由使用者確認候選根目錄或輸入 -WowRoot 改用明確根目錄。
  • Status／確認畫面必須列出 Retail、PTR、XPTR 三通道的目錄與完整 ProductVersion。互動選 PTR 或 XPTR 時才詢問是否同時加入 Retail；noninteractive 命令不得暗中加入 Retail。
  • 來源、目標與父層只要發現 SymbolicLink、Junction 或任何 Reparse Point，即 fail-closed，禁止追蹤、刪除、解除、覆蓋或自動重建。每次執行都要重新檢查，不得沿用舊快照。
  • 2026-08-21 現況：Retail/PTR 12.1.0.69382、XPTR 12.0.7.68887，三個 EventAlertMod 目標均為 physical，但目前只有 PTR 含 EventAlertMod.toc，Retail/XPTR 尚缺該檔；Test-LocalWoWEnvironment 為 1/3，不能宣稱三通道 ready。Deploy Status/DryRun 三通道通過只代表可安全部署前檢，尚未實際部署；先前 Retail/XPTR link blocked 的結果保留於歷史紀錄，不能取代本次 Status。

本節覆蓋本文較早的舊根命令與內容描述；舊段落保留作歷史證據。本輪文件更新後已以 EAM_DOCS_OFFLINE=1 離線重建 docs_html，未使用外部翻譯服務。

快速指令

使用者輸入「打包」時執行：

pwsh -NoProfile -File .\Deploy\Build-Package.ps1

使用者輸入「打包原始碼」時（已停用）：

註：自 2026-09-04 起，本機不再打包 SRC 版本，由 GitHub Release 原生自動打包提供。

使用者輸入「發布至 CurseForge」時執行：

pwsh -NoProfile -File .\Deploy\Upload-CurseForge.ps1

使用者輸入「模擬發布」時執行：

pwsh -NoProfile -File .\Deploy\Upload-CurseForge.ps1 -DryRun

需要部署時先檢查狀態，再由互動選單確認版本與目標：

pwsh -NoProfile -File .\Deploy\Deploy-EventAlertMod.ps1 -Action Status
pwsh -NoProfile -File .\Deploy\Deploy-EventAlertMod.ps1

封裝命令會修改 Dist/；部署選單只有在使用者最終確認且所有前檢通過後才會寫入 WoW。

版本命名

TOC 版本名稱必須符合：

EventAlertMod_資料片簡稱_打包年月日

目前資料片名稱固定為：

MN

範例：

## Version: EventAlertMod_MN_20260504

備用檔名

zip檔名必須符合：

EventAlertMod_資料片簡稱_打包年月日_打包時分秒.zip

範例：

EventAlertMod_MN_20260504_205216.zip

插件包內容契約

  • 唯一來源是專案根的完整 EventAlertMod/ 實體目錄；ZIP 頂層固定為 EventAlertMod/。
  • 封裝整棵來源樹，不維護可能漏掉 Managers/ 或未來模組的手工白名單。
  • 建立前強制檢查 TOC、TOC 引用檔、Managers/AlertManager.lua、Managers/AuraRuleCompiler.lua、README、changelog、SVG 與 Reparse Point 邊界。
  • 根目錄與插件內的 README／changelog 必須各自 SHA-256 相同。
  • .AI/、Deploy/、Dist/ 與 Git metadata 不會進插件包，因為它們不在插件來源樹內。

WTF 存檔備份／還原

Deploy-EventAlertMod.ps1 的 W／U 選單與 Backup／Restore 命令只處理選定版本通道的 WTF EventAlertMod 相關檔案。備份保留相對於版本根目錄的 WTF/... 路徑，manifest.json 記錄通道、版本與 SHA-256；還原前會建立 rollback 備份。一般插件部署不檢查 Wow.exe／WowT.exe 執行狀態，也不會因程序仍在執行而拒絕覆蓋；Reparse Point、路徑越界與雜湊不符仍維持 fail-closed。

可選參數

只驗證、不建立 ZIP：

pwsh -NoProfile -File .\Deploy\Build-Package.ps1 -DryRun
pwsh -NoProfile -File .\Deploy\Build-SourcePackage.ps1 -DryRun

指定輸出目錄或套件標籤：

pwsh -NoProfile -File .\Deploy\Build-Package.ps1 -OutputDirectory <目錄> -PackageLabel <標籤>

-SkipLuaCheck 與 -SkipFlowValidation 只供診斷工具故障；正式發布不得使用。專案 source 包只有 -OutputDirectory 與 -DryRun。

驗證要求

正式插件包預設必須完成：

  • TOC 與完整來源樹、必要 Managers、README/changelog 同步、敏感檔案及 Reparse Point 檢查。
  • .AI/Tools/CheckLuaSyntax.ps1。
  • .AI/Tools/Run-FlowValidation.ps1 -Suite all。
  • .AI/Tools/Test-ValidationContracts.ps1。
  • ZIP 解壓後 inventory、頂層目錄與 SVG 條目驗證。
  • 產生 ZIP、.sha256 與 .inventory.json。

專案 source 包必須排除 Dist/、本機附件、.AI/patch-temp/，並以 leaf 規則排除任意深度的 .git/、backup/、.trash_*/、TestResults/、快取、log 與既有 ZIP；同時保留 .vscode/、.codex/、.AI/skills/ 與 .AI/docs_html/。

HTML 說明檔案轉換

.AI/Docs/*.md 或 .AI/AGENTS.md 修改後，在專案根執行：

$env:EAM_DOCS_OFFLINE='1'
python .\.AI\Tools\batch_convert_docs.py

輸出位於 .AI/docs_html/。Markdown 原檔仍是 AI 與開發唯一 Facts-of-Truth；HTML 只供人類閱讀。離線模式不得把全文送往外部翻譯服務，也不再建立根目錄 readme.html。

注意事項

  • 資源成功不代表WoW正式服實機驗證完成。
  • 若 TOC ## Version 與當日日期不一致，壓縮工具會停止。
  • 發布前仍需依 .AI/Docs/06_TEST_PLAN_RETAIL.md 做正式服實機測試。
  • 封裝 gate 通過仍只代表離線契約，不能取代 _ptr_／_xptr_ 真人矩陣。

SVG 素材封裝契約

  • 正式副檔名白名單必須包含 .svg；否則本機符號連結可顯示、GitHub Release ZIP 卻會靜默缺素材。
  • Alpha 6 封裝至少必須含 Media/SVG/eam-minimap.svg、Media/SVG/eam-svg-probe.svg、Core/ProfileCodec.lua 與 UI/ProfileCodecPanel.lua，並繼續排除 Tests、TestResults、Tools、backup 與本機 deploy。
  • Validation Contracts 會斷言 SVG 為自包含靜態素材且無 script／href／data URI；完整來源樹封裝不可漏掉 .svg。
  • Release ZIP 建立後仍須列出壓縮內容確認 SVG 條目存在；本機 deploy 資料夾不得提交或重複打包。

GitHub Alpha 手動發布邊界

  • .github/workflows/release.yml 目前只保留停用殼：workflow_dispatch 且 job if: false。不得為 Alpha 6 移除 gate，也不得觸發 BigWigs packager。
  • 正式流程是在本機執行 Deploy/Build-Package.ps1 與 Deploy/Build-SourcePackage.ps1，檢查兩份 ZIP 清單與 SHA-256，再以 gh release create <tag> <addon.zip> <source.zip> --prerelease 上傳 GitHub Release。
  • GitHub Release 不等於 CurseForge／WoWInterface 發布；-w、-p 外部目標本輪不使用。
  • tag 必須指向已通過 gate 且已推送的 commit；ZIP 不提交 Git。插件包只含 EventAlertMod/，source 包依排除契約移除本機衍生物。

CurseForge 本機發布與 Token 安全契約

  • 100% 本機隔離原則：任何平台發布 Token（CurseForge API Token、WoWInterface Token、Personal Access Token）嚴禁以明文寫入任何檔案、禁止提交 Git、禁止出現在公開對話中。
  • Windows DPAPI 雙重加密防護：本機 Token 統一使用 Windows DPAPI 加密保存於 .AI/API_TOKEN.SEC，綁定當前 Windows 登入帳號，禁止上傳與打包。
  • 發布工具規範：手動發布統一由 Deploy/Upload-CurseForge.ps1 執行，支援 CLI 模式與詢問模式，並提供 -DryRun 模擬模式；上傳時於記憶體中解密並自動遮蔽輸出。
  • CI 凍結原則：GitHub Actions 發布流程維持停用，未獲授權不得配置任何雲端發布腳本。

CurseForge Budget Guide

This file defines publishing resource rules for EventAlertMod Retail rewrite.

2026-08-21 New root packaging and deployment management (current)

Plug-in ZIP

  • The only source is D:\Project_EventAlertMod\EventAlertMod, not Core/, UI/ or Dist staging staging scattered from the root directory.
  • ZIP must be EventAlertMod/ exact tree, keep EventAlertMod.toc, Core/, Data/, Debug/, Locale/, Managers/, Media/, Services/, UI/ in the plug-in folder and public instructions within the plug-in; not included in .AI, Deploy, Dist, testing, backup, or native deploy.
  • The product is written to D:\Project_EventAlertMod\Dist; Dist is ignored. The local product area is not submitted to Git and is not directly deployed as the AddOn source.

Source code ZIP (2026-09-04 deactivation statement)

  • Deactivation Specification: Starting from 2026-09-04, GitHub Release will automatically package the complete source code (zip and tar.gz) for the version when releasing the Tag. The local release process completely deactivates project SRC packaging, and no longer uploads SRC attachments to GitHub Release to eliminate resource waste and repeated packaging.
  • Historical rules retained: The original script Deploy/Build-SourcePackage.ps1 is only used as historical evidence and AST contract static verification, and is no longer included in the daily or automated release process of the machine.

Deployment selection and security pre-check

  • Deploy/Deploy-EventAlertMod.ps1 first checks the Windows Registry, and then uses Deploy/DeploymentTargets.json's wowRoot as JSON fallback; in interactive mode, the user can confirm the candidate root directory or enter -WowRoot to use a clear root directory.
  • The Status/confirmation screen must list the directory of the three channels Retail, PTR, XPTR and the complete ProductVersion. Only when interactively selecting PTR or XPTR will you be asked whether to join Retail at the same time; noninteractive commands must not secretly join Retail.
  • As long as the source, target and parent layers find SymbolicLink, Junction or any Reparse Point, they are fail-closed and are prohibited from being tracked, deleted, released, overwritten or automatically rebuilt. Each execution must be rechecked and old snapshots must not be inherited.

Deploy Status/DryRun Passing the three-channel only means that the pre-check can be safely deployed, and has not yet been actually deployed; the previous result of Retail/XPTR link blocked is retained in the history record and cannot replace this Status. Alternate file name

example:

Plug-in package content contract

  • The only source is the complete EventAlertMod/ entity directory of the project root; the top level of ZIP is fixed to EventAlertMod/.
  • Encapsulate the entire source tree, without maintaining a manual whitelist that may miss Managers/ or future modules.
  • Forced checking of TOC, TOC reference files, Managers/AlertManager.lua, Managers/AuraRuleCompiler.lua, README, changelog, SVG and Reparse Point boundaries before creation.
  • The root directory and README/changelog in the plug-in must be the same as SHA-256.
  • .AI/, Deploy/, Dist/ and Git metadata will not be included in the plugin package because they are not in the plugin source tree.

WTF Archive Backup/Restore

The W/U menu and Backup/Restore command of Deploy-EventAlertMod.ps1 only process the WTF EventAlertMod related files of the selected version channel. The backup retains the WTF/... path relative to the version root directory, manifest.json records the channel, version and SHA-256; a rollback backup will be created before restoring. General plug-in deployment does not check the execution status of Wow.exe/WowT.exe, nor does it refuse to overwrite because the program is still executing; Reparse Point, path out-of-bounds, and hash inconsistency remain fail-closed.

Optional parameters

Only verify, do not create ZIP:

pwsh -NoProfile -File .\Deploy\Build-Package.ps1 -DryRun
pwsh -NoProfile -File .\Deploy\Build-SourcePackage.ps1 -DryRun

Specify output directory or package label:

pwsh -NoProfile -File .\Deploy\Build-Package.ps1 -OutputDirectory <目錄> -PackageLabel <標籤>

-SkipLuaCheck and -SkipFlowValidation are for diagnostic tool failure only; not for use in official releases. The project source packages only have -OutputDirectory and -DryRun.

Verification requirements

Formal plug-in package presets must be completed:

  • TOC Synchronization with full source tree, required Managers, README/changelog, sensitive archives and Reparse Point checks.
  • .AI/Tools/CheckLuaSyntax.ps1.
  • .AI/Tools/Run-FlowValidation.ps1 -Suite all.
  • .AI/Tools/Test-ValidationContracts.ps1.
  • ZIP After decompression, inventory, top-level directory and SVG entries are verified.
  • Generates ZIP, .sha256 and .inventory.json.

The project source package must exclude Dist/, native attachments, .AI/patch-temp/, and use leaf rules to exclude .git/, backup/, .trash_*/, TestResults/, cache, log and existing ZIP at any depth; while retaining .vscode/, .codex/, .AI/skills/ and .AI/docs_html/.

HTML Description file conversion

After modifying .AI/Docs/*.md or .AI/AGENTS.md, execute at the project root:

$env:EAM_DOCS_OFFLINE='1'
python .\.AI\Tools\batch_convert_docs.py

The output is located at .AI/docs_html/. The original Markdown file remains the only Facts-of-Truth in AI and development; HTML is for human reading only. Offline mode must not send the full text to an external translation service, and the root directory readme.html will no longer be created.

Notes

  • The successful resource does not mean that the official WoW server verification is completed.
  • If TOC ## Version is inconsistent with today's date, the compression tool will stop.
  • Before release, it is still necessary to conduct Retail server testing according to .AI/Docs/06_TEST_PLAN_RETAIL.md.
  • The encapsulation gate pass still only represents the offline contract and cannot replace the _ptr_/_xptr_ real-life matrix.

SVG Material Encapsulation Contract

  • The official file extension whitelist must include .svg; otherwise, local symbolic links can be displayed, but GitHub Release ZIP will silently lack material.
  • Alpha 6 package must contain at least Media/SVG/eam-minimap.svg, Media/SVG/eam-svg-probe.svg, Core/ProfileCodec.lua and UI/ProfileCodecPanel.lua, and continue to exclude Tests, TestResults, Tools, backup and native deploy.
  • Validation Contracts will assert that SVG is a self-contained static material and has no script/href/data URI; the complete source tree encapsulation must not miss .svg.
  • After Release ZIP is created, the compressed content must still be listed to confirm that the SVG entry exists; the local deploy folder must not be submitted or repackaged.

GitHub Alpha manual publishing boundaries

  • .github/workflows/release.yml currently only retains the deactivated shells: workflow_dispatch and job if: false. Gates must not be removed for Alpha 6, and the BigWigs packager must not be triggered.
  • The formal process is to execute Deploy/Build-Package.ps1 and Deploy/Build-SourcePackage.ps1 on the local machine, check two ZIP lists and SHA-256, and then upload GitHub Release with gh release create <tag> <AddOn.zip> <source.zip> --prerelease.
  • GitHub Release is not equal to CurseForge/WoWInterface release; -w, -p external targets are not used in this round.
  • The tag must point to a commit that has passed the gate and been pushed; ZIP does not commit Git. The plugin package only contains EventAlertMod/, and the source package removes native tokens according to the exclusion contract.

CurseForge Native release and Token security contract

  • 100% Native Isolation Principle: Any platform publishing Token (CurseForge API Token, WoWInterface Token, Personal Access Token) is strictly prohibited from writing any files in clear text, submitting Git, and appearing in public conversations.
  • Windows DPAPI double encryption protection: The local Token uses Windows DPAPI and is encrypted and stored in .AI/API_TOKEN.SEC. It is bound to the current Windows login account and prohibits uploading and packaging.
  • Publishing Tool Specification: Manual publishing is uniformly executed by Deploy/Upload-CurseForge.ps1, supports CLI mode and query mode, and provides -DryRun simulation mode; it is decrypted in memory and automatically masks the output when uploading.
  • CI Freezing Principle: GitHub Actions release process remains disabled, and no cloud release scripts may be configured without authorization.
