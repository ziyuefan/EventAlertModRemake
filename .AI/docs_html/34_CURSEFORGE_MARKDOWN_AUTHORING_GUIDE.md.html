CurseForge Markdown 與 HTML 排版注意事項與避坑實戰報告

報告對象：EventAlertMod 專案開發與發布團隊
制定日期：2026 年 9 月 27 日
環境基準：CurseForge Web & App 平台、HTML5 Living Standard、Cloudflare WAF 穿透管線

一、 核心摘要 (Executive Summary)

在 CurseForge (CF) 平台編輯專案首頁說明（Description）或長篇 Markdown 時，經常會遇到「在編輯器預覽完全正常，但一按儲存（Save）發布到前台主頁後，排版全部擠成一坨、甚至整個收合區塊徹底崩壞吞噬」的極度詭異問題。

本報告基於 Chrome DevTools 對 CurseForge 前台真實 DOM 的逆向審查與實機注入驗證，揭示其前後端雙軌渲染架構的運作原理，並制定出一套「100% 免疫後端過濾器清洗、永久不崩壞」的標準排版規範。

二、 CurseForge 雙軌渲染機制與「預覽陷阱 (Preview Trap)」

CurseForge 的文章渲染管線存在致命的前後端脫節：

  1. 編輯與預覽階段（Client-side Preview）：
  2. 依賴瀏覽器端本地的純 JavaScript 引擎即時解析 Markdown 或 HTML。
  3. 此時尚未進入後端伺服器，因此不論語法多麼複雜、是否包含未閉合標籤或 <li> 列表，預覽畫面都會呈現出完美的假象。
  4. 儲存入庫與前台展示（Server-side Sanitizer）：
  5. 點擊「Save」後，文章會傳入後端伺服器，被強制通過一套嚴格但規格殘缺的 HTML Sanitizer（伺服器端過濾器） 進行清洗。
  6. 驗收鐵則：絕不相信 Preview 標籤頁的預覽效果，唯一的真理是「實際儲存後前台公開頁面的真實 DOM」。

三、 後端 Sanitizer 的三大破壞性行為與排坑

1. <li> 標籤被無差別洗白剝離

  • 現象：經 DevTools 實地查詢 document.querySelectorAll('.project-description li')，結果為 0。
  • 後果：CurseForge 的過濾器白名單放行了 <ul> 與 <ol>，但卻會把所有 <li> 與 </li> 標籤硬生生剝離！
  • 排版災難：失去 <li> 的區塊換行與清單樣式後，所有清單項目直接在 <ul> 裡裸奔，文字首尾相連，被瀏覽器擠壓成一整坨難以閱讀的單行文字。

2. 巢狀 <ul> 引發跨版本標籤吞噬骨牌效應 (Cascading Unclosed Tags)

  • 現象：當使用者在收合內寫了多層縮排列表（如大分類包含子清單）時，<li> 被洗掉後，外層 <ul> 內部會直接包含內層 <ul>。
  • 後果：HTML 解析器在處理失衡的 DOM 時會陷入容錯混亂，導致最外層的 </ul> 與 </div> 被丟棄。
  • 排版災難：未閉合的容器會一路向下「吞噬」後續所有的章節與版次。實機曾測得高達 15 層深度的俄羅斯套娃收合（Alpha 8.7 吞了 8.6，8.6 吞了 8.5，最後連最底部的「相容性」與「連結」全被吞入）！

3. HTML5 <details markdown="1"><summary> 折疊標籤失效

  • 現象：CurseForge 的富文本清洗器會完全剝離 HTML5 <details markdown="1"> 與 <summary>，或直接將其展開打平，無法形成原生折疊效果。

四、 核心排版規範與鐵律 (The Golden Rules)

為了在 CurseForge 實現 100% 穩定、跨平台完美呈現的排版，必須嚴格遵守以下五大鐵律：

鐵律 1：收合容器統一採用官方標準 <div class="spoiler">

CurseForge 唯一官方原生支援的折疊語法為 <div class="spoiler">： - 標題必須置於外部：例如 <h2>標題</h2> 或 <h4>版次</h4> 放容器外，避免被預設隱藏。 - 嚴禁使用巢狀收合 (Avoid Nested Spoilers)：全檔必須採「單層一級平鋪架構」。例如「📜 版本更新歷史」大標題常駐展開，其下 21 個歷史版次各自作為獨立的單層 <div class="spoiler">。

鐵律 2：全面摒棄 <ul>、<ol>、<li>，改用實體符號 + <br><br>

既然後端 Sanitizer 會洗掉 <li> 且 <ul> 會引發吞噬，最純粹穩健的解法就是在描述檔中徹底不使用任何列表標籤： - 一級條目：自帶專屬 Emoji（如 🔮、🎯、📖）或數字標記，每條結尾加上 <br><br> 產生舒適的段落空行。 - 二級子項目：一律以 HTML 實體圓點 &bull;&nbsp;（即 •）開頭，結尾加上 <br><br>。 - 無標籤可被吃：沒有 <li> 就絕不會被剝離，沒有 <ul> 就絕不會發生跨版本吞噬！

鐵律 3：現代 HTML5 空標籤規範（杜絕 <tag /> 自閉合）

  • 依據現代 HTML5 (Living Standard) 規範，所有空元素 (Void Elements) 一律採用標準單標籤：
    • 換行：<br>
    • 段落間隙：<br><br>
    • 分隔線：<hr>
    • 圖片：<img src="..." width="100%" alt="...">
  • 嚴禁使用帶有斜線之 XHTML 舊式閉合簡寫（如 <br />、<hr />、<img ... />）。

鐵律 4：表格全面 HTML 語意化 (Table HTML-First)

  • Markdown 原生表格（|---|）在包含代碼標籤或遇到收合邊界時極易破版。
  • 一律採用原生 <table>、<thead>、<tbody>、<tr>、<th>、<td> 結構，圖片欄位加上 width="100%" 自適應寬度。

鐵律 5：圖片 100% 對齊 CurseForge Attachments CDN

  • 嚴禁使用 GitHub raw（raw.githubusercontent.com/...）或外部圖床，否則會觸發 Cloudflare 防盜鏈警告或破圖。
  • 必須將截圖上傳至 CurseForge 專用附件空間，並採用 https://media.forgecdn.net/attachments/... 官方 CDN 網址。

CurseForge Markdown and HTML Typesetting precautions and pitfall avoidance practical report

Report to: EventAlertMod Project Development and Release Team Date of Enactment: September 27, 2026 Environmental Benchmarks: CurseForge Web & App Platform, HTML5 Living Standard, Cloudflare WAF Penetration Pipeline

1. Core Summary (Executive Summary)

When editing the project homepage description (Description) or long Markdown on the CurseForge (CF) platform, we often encounter the extremely weird problem of "The preview in the editor is completely normal, but after pressing Save (Save) to publish to the front homepage, the layout is all squeezed into a lump, and even the entire collapsed block is completely collapsed and swallowed.". This report is based on Chrome DevTools's reverse review and real-machine injection verification of CurseForge's front-end real DOM, revealing the operating principle of its front-end and back-end dual-track rendering architecture, and formulating a set of standard layout specifications that are "100% immune to back-end filter cleaning and never crash"**.

2. CurseForge Dual-track rendering mechanism and "Preview Trap"

Article by CurseForge There is a fatal front-end and back-end disconnect in the rendering pipeline:

（尚未經後端清洗：<li> 完好、排版看似正常！）"] end subgraph Server ["☁️ CurseForge 後端伺服器（點擊 Save 儲存後）"] D["點擊 Save 儲存"] --> E["後端 HTML Sanitizer 安全過濾清洗器"] E -->|無差別洗白| F["<li> 標籤被全面剝離！只留 <ul>"] E -->|嵌套結構錯亂| G["多層 <ul> 找不到閉合，外層 </ul></div> 被丟棄！"] end subgraph Public ["🌐 前台公開主頁（真實訪客視角）"] F --> H["所有清單文字黏成同一大坨長字串"] G --> I["未閉合容器骨牌式向下吞噬 15 層版本收合！"] end C -.->|"高度欺騙性假象"| D
  1. Editing and Preview Phase (Client-side Preview):
  2. Rely on the pure JavaScript engine native to the browser to parse Markdown or HTML on the fly.
  3. We haven't entered the backend server yet, so the preview will appear to be perfect, no matter how complex the syntax, including unclosed tags or <li> lists.
  4. Storage and front-end display (Server-side Sanitizer):
  5. After clicking "Save", the article will be transferred to the back-end server and forced to pass through a strict but incomplete set of HTML Sanitizer (server-side filter) for cleaning.
  6. Iron Rule of Acceptance: Never trust the preview effect of the Preview tab, the only truth is "the real DOM of the front-end public page after actual storage".

3. Three major destructive behaviors and pitfalls of back-end Sanitizer

1. <li> labels are washed and stripped indiscriminately

  • Phenomena: After DevTools field inquiry document.querySelectorAll('.project-description li'), the result is 0.
  • Consequences: The filter whitelist of CurseForge allows <ul> and <ol>, but will strip off all <li> and </li> tags!
  • Typesetting disaster: After losing the block wrapping and list style of <li>, all list items run naked directly in <ul>, with the text connected end to end, and the browser squeezes it into a single line of text that is difficult to read.

2. Nested <ul> causes cross-version tags to devour domino effect (Cascading Unclosed Tags)

  • Phenomena: When the user writes a multi-layer indented list in a collapse (such as a large category containing sub-lists), after <li> is washed away, the outer layer <ul> will directly contain the inner layer <ul>.
  • Consequences: The HTML parser will get into a fault-tolerant mess when processing an unbalanced DOM, causing the outermost </ul> and </div> to be discarded.
  • Typesetting disaster: The unclosed container will "swallow" all subsequent chapters and editions all the way down. The actual machine has measured up to 15 layers of Russian matryoshka doll closing (Alpha 8.7 swallowed 8.6, 8.6 swallowed 8.5, and finally even the "compatibility" and "connection" at the bottom were swallowed)!

3. HTML5 <details markdown="1"><summary> Folding label invalid

  • Phenomena: The rich text cleaner of CurseForge will completely peel off HTML5 <details markdown="1"> and <summary>, or directly expand and flatten them, unable to form a native folding effect.

4. Core typesetting standards and iron rules (The Golden Rules)

In order to achieve 100% stable, cross-platform perfectly rendered typesetting in CurseForge, the following five iron rules must be strictly observed:

Iron Rule 1: All containers must be closed using the official standard <div class="spoiler">

CurseForge The only officially supported folding syntax is <div class="spoiler">: - The title must be placed outside: for example <h2>標題</h2> or <h4>版次</h4> placed outside the container to avoid being hidden by default. - Avoid Nested Spoilers are strictly prohibited: The entire structure must adopt a "single-layer, one-level tile structure". For example, the big title "📜Version Update History" is always expanded, and the 21 historical versions under it each serve as independent single-layer <div class="spoiler">.

Iron Rule 2: Completely abandon <ul>, <ol>, <li>, and use entity symbols + <br><br> instead

Since the back-end Sanitizer will wash out <li> and <ul> will cause swallowing, the purest and most robust solution is to not use any list tags in the description file at all: - Level 1 Entry: Comes with its own exclusive Emoji (such as 🔮, 🎯, 📖) or number tags, and adds <br><br> at the end of each entry to create a comfortable paragraph blank line. - Second-level sub-projects: always start with HTML entity dot &bull;&nbsp; (that is, •), and add <br><br> at the end. - No tags can be eaten: Without <li>, it will never be stripped, and without <ul>, cross-version swallowing will never occur!

Iron Rule 3: Modern HTML5 empty label specification (prevent <tag /> from self-closing)

  • According to the modern HTML5 (Living Standard) specification, all void elements (Void Elements) use standard single tags:
    • Line break: <br>
  • Paragraph gap: <br><br>
    • Separator: <hr>
    • Picture: <img src="..." width="100%" alt="...">
  • It is strictly prohibited to use the XHTML old-style closed abbreviation with a slash (such as <br />, <hr />, <img ... />).

Iron Rule 4: The table is comprehensive HTML Semanticization (Table HTML-First)

  • Markdown native tables (|---|) are easily broken when they contain code tags or encounter collapsing boundaries.
  • Always use the native <table>, <thead>, <tbody>, <tr>, <th>, <td> structures, and add width="100%" adaptive width to the image field.

Rule 5: Images are 100% aligned CurseForge Attachments CDN

  • It is strictly prohibited to use GitHub raw (raw.githubusercontent.com/...) or external image beds, otherwise it will trigger Cloudflare anti-hotlink warning or broken images.
  • Screenshots must be uploaded to the CurseForge dedicated attachment space and use the https://media.forgecdn.net/attachments/... official CDN URL.
